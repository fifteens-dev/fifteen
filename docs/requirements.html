Fifteens / 15s

15s 要件定義

夜に通知が来て、友達と「今日の1曲」を出し合う音楽SNS。 この文書は、現在コードに入っている仕様をそのまま書き起こしたものです。 構想ではなく、動いているものを記述しています。

2026-10-06 時点 v1.7.0 (69) iOS / Flutter + Firebase

01サービスの骨子

1日1回、全員に同じ時刻の通知が届く。受け取った人はその日聴いた曲から1曲を選んで投稿する。 投稿はカードの形で友達のタイムラインに並び、裏返すとその人の「今の音楽の顔」が見える。

設計上の軸は 同時性 です。いつでも投稿できるのではなく、 毎晩決まった時刻から始まる限られた窓の中で全員が投稿する。 この窓を 15s Day（＝1サイクル）と呼びます。

021日のサイクル

サイクルの境界は、サーバーが通知を実際に発火した時刻 （music_memory_state/current.notifiedAt）です。 端末の時計ではなくこの値を基準にするので、全員のサイクルが揃います。

21:00
通知が届く
JST 固定。5分おきに走る定期処理が、その日まだ送っていなければ送る。発火時刻を記録し、ここがサイクルの開始になる。
21:00 – 24:00
投稿できる
曲を選んで投稿する。この窓の中で投稿したものが「期限内投稿」。写真を足せるのもこの間だけ。
24:00 以降
Late 投稿
投稿自体は翌日の通知までできるが isLate が付く。写真は足せない。
通知時刻 21:00 JST 固定。以前は 19:00–23:30 のランダムだった。
締切 notifiedAt の JST 暦日の 24:00（＝翌 0:00）。
投稿の上限 無し。1サイクルに何度でも投稿できる。
（WATERFALLS のようなイベントでは別途 1日1投稿に制限する）
自動で開く 21:00〜24:00 に未投稿のままアプリを開くと、投稿フローが自動で開く。1サイクルにつき1回だけ。

03投稿

曲の選び方

連携している音楽サービスで入口が分かれ、そこから先は同じ最終確認画面に合流します。

サービス入口選べる曲
Apple Music Music Memory カルーセル 再生履歴から。カードを横に送って選ぶ
Spotify ほか Vibe シート 検索して選ぶ

投稿までの流れ

  • 曲を選び「この曲で続ける」を押すと、最終確認画面がホームの上に重なって開く
  • 最終確認画面では曲が15秒プレビュー再生される
  • 写真を足す場合は、カード上の「写真を追加する」バーから
  • 投稿すると完了シートが出る（写真を選んでいた場合は出さずにそのまま紐づける）
裏面の集計は投稿前に走らせています。 top artists の集計は再生履歴や Spotify を叩くので時間がかかります。 投稿してから追いかけて書くと、直後に読み直すホームで裏面が空のまま出てしまうため、 最終確認画面を開いた時点で集計を始め、投稿データに最初から入れています。

04投稿カード

カードは 363×645 を基準寸法として組み、枠が違うときは丸ごと拡縮します。 表面はアルバムアートの上に下 294px ぶんのグラデーションを敷く構成。裏面は中身が3種類あります。

裏面出る場所中身
プロフィール ホームのタイムライン top artists 3人 / recent choice 3曲。投稿時点の値を焼き込んである
写真 自分の Music Memory のみ 全面に写真。上に投稿者・曲名・リアクション
曲情報 旧フロー由来の投稿 歌詞カードを使っていた頃の裏面

写真がある投稿は写真の裏面が最優先で、プロフィールより先に判定されます。 また写真がある日は、カードが裏面から開きます。

05写真

投稿に1枚だけ添えられます。写真は公開しません。 本人が自分の Music Memory から開いたときにだけ見えます。

足せる期間 その日の 24:00 まで。締切は投稿と同じ notifiedAt 基準。
使える写真 その場で撮るか、サイクルの開始日に撮った写真のみ。昔の写真を当日インポートしても通らない（判定は保存日ではなく撮影日時）。
置き場 Storage は private_photos/{uid}/、メタ情報は post_photos/{postId}。公開画像とは完全に別系統。
枚数 1投稿につき1枚。付いた投稿には追加のバーを出さない。
Storage のルールだけでは非公開になりません。 ダウンロード URL に付く ?token= はセキュリティルールを迂回するため、 URL を知っている人はルールに関係なく閲覧できます。URL そのものを post_photos 経由でしか配らないことで守っています。

06Music Memory

自分の投稿をカレンダーで振り返る画面。月ごとに、新しい順に3ヶ月ずつ読み込みます。 日付のグルーピングは投稿の createdAt の暦日です。

  • 日をタップすると、その日の投稿カードが開く
  • 写真がある日は裏面（写真）から開く
  • タブに入るたびカレンダーを読み直す（投稿した直後に戻ってきても最新が出るように）

07公開範囲

対象見える人
投稿カードの表面フォロワー
裏面（プロフィール）フォロワー
添えた写真本人のみ
Music Memory カレンダー本人のみ
「期限内に投稿した人だけが他人の裏面を見られる」というゲートは、現在かかっていません。 判定そのもの（postStatusInCurrentCycle）は実装されていますが、 ホームのタイムラインは裏返しを無条件に許可しています。 仕様として戻すかどうかは未決です。

08音楽サービス

top artists / recent choice の集計元は、連携しているサービスで変わります。

サービスtop artists の集計元理由
Apple Music 再生履歴 直近100曲 履歴 API が全ユーザーで使える
Spotify 直近7日の自分の投稿 履歴 API が一般ユーザーで使えない
Spotify で再生履歴を使えない理由。 Development Mode では許可リストに入れた5人（かつ Premium）しか Web API を叩けません。 制限を外す Extended Quota Mode は法人であることと月間25万アクティブユーザーが条件で、 当面申請できないため、投稿ベースの集計で代替しています。

Apple Music の Developer Token はバックエンドで .p8 から都度署名して発行します。 失効してもアプリの再配信は不要で、関数の再デプロイだけで済みます。

09招待

友達が居ないと何も起きないサービスなので、登録の最後に招待画面を1枚挟みます。 招待カードは QR 付きで、Instagram のストーリーにそのまま流せます。

経路URL遷移先
プロフィール QR/u/{uid}そのユーザーのプロフィール
招待コード/invite/{code}招待ページ
アプリ未所持App Store id6758916042ダウンロード後、招待情報を引き継ぐ
  • 招待リンク経由でインストールした場合、招待コードの入力をスキップして自動で招待済み扱いにする
  • App Store へ送るときも招待コードを保持する（戻ってきた人向け）

10ウィジェット

ホーム画面に置く小ウィジェットで、友達が今 Apple Music で聴いている曲を表示します。 誰も聴いていなければ「友達は音楽を聴いていません。」と出します。

仕組み 他人の端末の再生状態を直接知る API は無い。各自が自分の再生状態を now_playing/{uid} に書き、友達はそれを読む。
更新 アプリを開いたときと、iOS のバックグラウンド更新から。間隔は OS の裁量。
鮮度 30分より古い報告は「聴いていない」とみなす。何時間も前の曲を「今」と言わないため。
表示 10分ごとに友達を切り替えて表示。背景はすりガラス。

書き込みは Swift 側で完結させています。バックグラウンド更新の持ち時間は短く、 Flutter エンジンを起こすと起動だけで使い切ってしまうためです。

11未適用・保留

実装はあるが効いていないもの、意図的に止めているもの、着手していないものの一覧です。

裏面閲覧のゲート 未適用 期限内投稿者だけに裏返しを許す判定は実装済みだが、タイムラインに適用されていない。
いいね・コメント 停止中 kCommentsEnabled = false で切っている。UI のコードは残してあり、true に戻せば復活する。
Vibe 非表示 ストーリーバーもトピック投票も全面非表示。過去の Vibe 投稿は投稿カード形式で表示している。
チュートリアル 保留 画面一式は残してあるが導線が無い。文言待ち。
歌詞カード 旧フロー 投稿フローからは外れている。過去の投稿を表示するために描画側は残っている。
